# 对话卡片样式（下游）

`cardStyles` 只控制对话内容区的外观，不影响输入框、补全菜单、审批框、问卷、浮窗或侧栏。如果不做任何配置，界面会保持原有的默认外观。

> 说明：本文中提到的“透明”，指的是不绘制背景色或使用极淡的实色背景，而不是终端不支持的 Alpha 半透明效果。

## 启用与配置层级

在 `~/.dsh-tui/settings.json` 现有的 `values` 中加入以下字段（保留你的其他设置）：

```json
{
  "version": 1,
  "values": {
    "cardStyles": {
      "preset": "pi-like",
      "kinds": {
        "tool": { "previewLines": 6 },
        "summary": { "defaultExpanded": true }
      }
    }
  }
}
```

你也可以在 Cordis/profile 里 `dsh-tui` 插件行的 `config.cardStyles` 中写同样的配置对象。配置优先级遵循以下规则：

- **用户配置整体优先**：`settings.json` 中的整个 `cardStyles` 对象会直接覆盖部署层的配置，**两者不会深合并**。哪怕用户只写了 `kinds`，也不会继承部署配置里的 `preset`。
- **生效方式**：部署配置需要重启生效。运行中修改用户配置文件可能会即时应用，但重启是最可靠的方式。本功能不新增 `/settings` 界面控件，也不复用 Agent 的 `/preset`。
- **内部覆盖顺序**：单个配置对象内部按 **基础方案 → `common` → `kinds.<类型>`** 逐层覆盖，其中的状态色 `states` 会按各个状态单独合并。切换 `preset` 不会清空已有的自定义覆盖。

两套预设方案的默认表现如下：

| 方案 | 默认表现 |
| --- | --- |
| `legacy`（默认） | 保持原有背景、布局与折叠行为；工具背景继续由 `toolBackground` 决定 |
| `pi-like` | 普通卡片无边框，上下文通知保留左侧紫线。用户消息使用柔和可辨的底色；工具和子代理使用柔和的状态底色，保留原有缩进和零内边距。`custom`（通用自定义卡片、技能、已适配命令）使用独立的紫色底面，上下左右各留 1 格内边距，展开后标签、标题与正文分层展示。后台任务默认透明且组内紧贴，其他普通卡片之间至少留 1 行不着色的空行。助手、思考块、摘要和 `other` 无背景填充 |

自定义卡片使用独立的颜色角色：`customMessageBackground`、`customMessageLabel`、`customMessageText`、`customMessageHint`，与工具状态色互不干扰。

- 无需额外配置 `kinds.custom`，`pi-like` 就会自动启用这套自定义卡面；如果显式配置了覆盖项，仍以你的覆盖为准。
- 配色逐色参考 Pi 1.4.0 的深浅色主题。在浅色主题下，正文和标签对卡面的对比度分别约为 3.98:1 和 4.36:1，不承诺达到 4.5:1 的 WCAG AA 标准；如果你需要更强的对比度，可以在自定义主题中调深这两个颜色角色。工具状态面的原有 AA 对比度门禁保持不变。

两套预设方案默认都不改变原有的折叠策略。切换到 `pi-like` 后，工具背景会由它接管，不再读取旧的 `toolBackground` 设置（但个人在 `cardStyles` 里的覆盖依然优先）。

在 `pi-like` 的暗色真彩模式下，Read、Edit、Write 三类工具会使用各自专属的低饱和底色，失败时统一保持玫瑰状态底；其他工具和子代理继续使用通用的状态底色。浅色主题继续沿用原有的状态色，低色档终端则会退回到可辨认的色槽以保证可读性。用户消息的底色会跟随终端背景色，暗色真彩下的 Edit 正文也会直接使用卡片底色，具体规则见下文。

## 卡片类型与可配属性

`kinds` 支持以下类型：

| 键 | 内容 | 支持的折叠配置 |
| --- | --- | --- |
| `user` | 用户消息、团队消息 | `defaultExpanded`（仅支持原有的超长单行裁剪） |
| `assistant` | 助手正文（含流式输出） | `defaultExpanded`（仅支持原有的超长单行裁剪） |
| `thinking` | 思考块 | `defaultExpanded`；`previewLines` 只控制流式输出时的滚动预览行数，不会为已结束的折叠块增加正文 |
| `tool` | 工具调用及结果 | `defaultExpanded`、`previewLines` |
| `subagent` | 子代理消息 | 无（保留原有的详情入口） |
| `job` | 后台任务 | `defaultExpanded` 只调整已有任务组的初始展开状态，不改变分组条件；`progressStyle` 控制对话卡片里的进度展示（见「Job 进度线」） |
| `notice` | 上下文通知（如 `tool-jobs`、`subagent-settled`） | 保留原有的点击、选中按 Enter 和 `Ctrl+O` 展开；不新增折叠配置 |
| `summary` | 压缩摘要 | `defaultExpanded`（折叠时为文字预览，不支持 `previewLines`） |
| `custom` | 通用自定义卡片、技能、已适配的命令结果卡片 | 保留宿主原有的 `Ctrl+O`、选中按 Enter 和点击交互 |
| `other` | 普通通知、中断提示、本地回显/输出、回合用量等 | 无 |

`kinds.custom` 控制的是整类自定义卡片的样式。如果你只想让**某一张**卡片显得更紧凑，应该在它的展示数据里声明 `density: 'compact'`（详见[自定义卡片规范](custom-cards.md)）。这只会去掉那一张卡的背景、边框、内边距和间隔，同时保留主题颜色、折叠和选中高亮，同类型的其他卡片不受影响。不要为了调整单张卡片去修改 `kinds.custom`。

`common` 和各类型的 `kinds.<类型>` 均支持以下属性：

| 属性 | 可选值与说明 |
| --- | --- |
| `background` | `none`、主题颜色键或合法的显式颜色 |
| `foreground` | 仅控制用户输入消息的文字颜色（其他类型忽略该字段）：主题颜色键或显式颜色；不填则沿用 `userPromptLabel`（DSH 主题橘红） |
| `bold` | 仅控制用户输入消息是否加粗（其他类型忽略该字段）：`pi-like` 默认 `false`，`legacy` 默认 `true`；类型覆盖优先于 `common` |
| `border` | `none`、`single`、`double`、`round`、`bold`、`singleDouble`、`doubleSingle`、`classic`、`arrow`、`dashed` |
| `borderColor` | 主题颜色键或显式颜色；开启边框但未指定颜色时默认使用 `promptBorder` |
| `paddingX` | 左右内边距，各 0–8 列 |
| `paddingY` | 上下内边距，各 0–4 行 |
| `gap` | 在原有行间距上额外增加 0–4 行。注意：`pi-like` 默认已为普通卡片留出 1 行空隙（后台任务组内不留）；如果显式设置了 `gap`，则会直接替换这个 1 行下限，按“原有行间距 + `gap`”计算，不会叠加 |
| `defaultExpanded` | 布尔值，仅支持上表中列出的对应类型；不填则继承原有行为 |
| `previewLines` | 1–40，仅对 `tool` 和流式 `thinking` 生效；给 `tool` 指定时同时覆盖文本和 diff 的预览行数（默认文本 3 行、diff 8 行） |
| `states` | 仅对 `tool`、`subagent`、`job` 生效，见「执行状态底色」 |
| `progressStyle` | `line` 或 `bar`；`common` 里可写，但只有 `job` 会读取，见「Job 进度线」 |

所有数值都会取整并限制在合法范围内；未知类型或非法字段会被直接丢弃并回退到方案默认值。颜色支持主题颜色键、`#rgb`/`#rrggbb`、`rgb()`、`ansi256()`、`ansi:` 等已有主题格式。请不要使用 8 位 hex 来期待半透明效果，终端不会按 Alpha 通道做合成。

`defaultExpanded` 只决定卡片的初始状态。用户原有的点击和 `Ctrl+O` 切换始终优先，默认展开的行也可以点击收起。`thinkingFold`、`jobGroupFold`、`foldTerminalCommand` 等原有设置依然各自生效，本功能不新增折叠交互方式。

## 状态标识与代码框

在 `pi-like` 方案下，子代理与 workflow 成员改用单列的状态字符：

- 运行中：聊天卡片里显示细小的 braille 旋转指示器，列表里显示点号。
- 成功：主题成功色的 `✓`。
- 失败：错误色的 `×`。
- 取消或状态未知：灰色的 `·`。

侧栏、团队列表、详情页和转录加载提示都会使用这套统一的克制字形，原有的状态文字依然保留。`legacy` 方案以及用户消息或工具正文里的 emoji 均不做改动。

回复中 fenced 代码块的边框样式遵循以下优先级：

1. 独立配置 `values.codeFrameStyle`（或部署配置 `config.codeFrameStyle`）中显式指定的 `light` 或 `full` 始终优先。
2. 当用户层和部署层都没有设置时，`pi-like` 默认使用 `full`，`legacy` 默认使用 `light`。

注意：`codeFrameStyle` 并不是 `cardStyles` 内部的字段。此外，极窄终端下会保留原有的无框降级样式，Edit 工具专用的 diff 视图也不受这个设置影响。

在 Powerline 样式下，实时任务计数会显示在主 HUD 行上；但如果加上计数会导致溢出区多折出一行，系统会自动省略这个计数，避免任务启停时上下挤动对话区域。完整任务列表仍可通过 `/jobs` 查看。

## 上下文通知卡

在 `pi-like` 方案下，通用上下文通知卡片采用左侧紫色细线搭配紫灰底色（暗色真彩为 `#19151f`，浅色为 `#f3eef7`）。

- 标题栏显示通知来源；折叠时摘要单独占下一行；展开后直接显示完整保存的正文，不再重复显示摘要。
- 它与用户卡片、执行状态卡片相互独立，不会根据正文里的 `completed`/`failed` 或退出码来猜测背景色。
- 在 256 色终端下回退为中性灰阶；在 16 色终端下只保留左侧线条与标签。

你可以通过 `cardStyles.kinds.notice` 覆盖通知卡片的背景、边框、间距和内边距：`background: "none"` 可取消底色，`border: "none"` 可取消左侧细线，指定常规边框则会改为完整四周边框。`legacy` 方案保留原有的通知样式。这里只改变持久化通知的界面展示，不会影响模型接收消息、唤醒机制、会话存储或任务状态。

## 工具分类底色

在 `pi-like` 的暗色真彩预设下，系统会按工具名（不区分大小写）给以下三类工具使用专属的底色。该底色覆盖卡片头部和正文，但保留原本的工具名字颜色：

| 工具 | 卡面底色 | 工具名字色（dark 主题） |
| --- | --- | --- |
| Read | 雾蓝 `#171F29` | `accent`（`#7DA1DE`） |
| Edit | 紫灰 `#211C29` | `toolNameMutate`（`#E5C07B`） |
| Write | 青灰 `#172321` | `toolNameMutate`（`#E5C07B`） |

这三类工具在“运行中”和“成功”时使用同一个分类底色，执行状态通过原有的图标、动画和文字区分；失败时则回退到失败状态底色。Bash 等其他工具、子代理和后台任务不使用这张分类表。

在浅色主题以及 256/16 色终端下，仍沿用原有的状态底色，避免把接近黑色的细腻色阶量化成刺眼的高饱和色块。只要你在配置中显式设置了 `background` 或对应 `states`，你的个人覆盖始终优先，关闭背景填充的效果也不受影响。

## 执行状态底色

除了上面提到的暗色真彩分类工具外，`pi-like` 使用一套低对比、贴近终端背景的通用状态底色来区分“执行中”、“成功”和“失败”：

- 后台任务（`job`）默认保持透明，只有在显式配置了 `states` 时才绘制状态底色。
- 所有状态符号和文字照常显示，状态映射只在界面渲染时进行，不修改会话事件或持久化记录。
- 取消、停止、终止及未知状态都使用普通卡面，不会冒充成功或失败。

配置示例：

```json
{
  "preset": "pi-like",
  "common": {
    "border": "round",
    "borderColor": "promptBorder"
  },
  "kinds": {
    "tool": {
      "states": {
        "running": "toolCardBackgroundDim",
        "success": "#183321",
        "failure": "#3a2028"
      }
    }
  }
}
```

普通 `background` 和 `states` 相互独立：修改 `background` 不会关闭动态状态底色。设置 `states.success: "none"` 表示成功时回退到普通卡面；如果你想彻底取消所有背景填充，需要同时把 `background` 和三个 `states` 都设为 `"none"`。

各色档下的默认通用状态色如下：

| 色档 | 暗色主题 | 亮色主题 |
| --- | --- | --- |
| 真彩（逐通道色） | 执行中 `#0d1013`（中性近黑）；成功 `#0e1b14`（极淡灰绿）；失败 `#21161d`（极淡豆沙玫瑰） | 执行中为当前主题的中性面；成功 `#e8efe9`（sage）；失败 `#f3e6ea`（rose） |
| 256 色 | `236` 灰（执行中）/ `23` 深青绿（成功）/ `95` 豆沙玫瑰（失败） | `254` 灰 / `151` sage / `181` rose |
| 16 色 | 黑（执行中）/ 蓝（成功）/ 红（失败） | 白 / 绿 / 亮红 |

关于各色档的说明：

- **真彩**：内置主题的真实渲染测试要求三态底色两两不同，且默认正文对比度至少达到 4.5:1。仅使用 ANSI 颜色名的暗色主题无法做逐通道配色，其执行中状态会回退到中性色槽。亮色主题的执行中状态如果取不到主题中性面，也会回退到对应色档槽位。
- **256 色**：显式选用有色槽位，防止 RGB 量化把成功和失败压成同一个颜色。但 256 色无法表达真彩下接近黑色的细腻微差（例如暗色执行中是 `#303030` 即 236），色差会比真彩更明显。
- **16 色**：使用可读的降级色槽，无法呈现柔和色盘，也不保证成功底色一定是绿色。
- **用户自定义与调色板**：对比度验证基于标准终端调色板，如果你自己修改过终端的 0–15 号颜色槽，视觉效果会随之改变。显式设置的 `states` 在任何色档下都按你指定的颜色绘制，区分度和可读性由配置者自行保证。关闭颜色输出时只保留状态符号，不再绘制背景区分。

在 tmux 中运行时，程序会在启动时自动检查当前 pane 所属会话的客户端能力：只有所有已连接的客户端都支持 `RGB` 时才保留真彩输出；如果存在不支持的客户端、没有已连接客户端、查询失败或超时，则保守降级到 256 色。这不需要修改 tmux 配置，支持 RGB 的正常会话也不必额外设置环境变量。原有的 `DSH_TUI_TMUX_TRUECOLOR=1` 仍可用来强制跳过该检查，`FORCE_COLOR=0/1/2` 也会继续尊重用户指定的色档。由于能力结果在启动时决定，连接环境变化后需要重启生效。

## Edit / diff 正文

在 `pi-like` 的真彩预设卡面下，Edit 类 diff 卡片的代码区（包括 unified 单栏和 split 双栏）会直接沿用整张卡片的底色。例如在暗色主题下，Edit 的紫灰底色会完整覆盖卡头、正文、上下文行、左侧粗 gutter 和双栏间隔，不再在里面单独铺一块黑底；浅色真彩下同样沿用对应卡面。

split 双栏的新增行和删除行仍会铺上各自的极淡衬底（新增灰绿、删除豆沙玫瑰），不会被卡片底色盖掉，且这层衬底在普通、选中和悬停状态下都会保留。语法高亮、diff 解析、双栏对齐和词级对比算法都不变，双栏中发生变化的词（changed words）仍会加粗并保留语义色。unified 和 split 共用 `src/components/diffAppearance.ts`。在 256 色和 16 色模式下，正文维持原有的终端底色；其中 16 色没有可用的淡色行衬底，仅靠词色区分增删。

这套自适应 diff 外观的适用范围与分层细节如下：

- **启用条件**：仅在「`pi-like` 且当前生效卡面来自方案预设」时启用。如果是 `legacy`，或者用户显式覆盖了 `background`/`states`，则维持原有外观。此外，它只作用于真实对比（正文带 patch，或 old/new 对且 `oldText !== null`）；新建文件的 Write 卡片不走这层重绘，而是和 Read、Bash 一样直接由卡片底色铺满正文（暗色真彩下 Write 为青灰底，Read 为雾蓝底）。
- **选中与悬停反馈**：选中（`messageActionsBackground`）和悬停（`toolCardBackground`）时，正文外层依然是整行真实的高亮底色，确保卡头、粗 gutter 和上下文行能看到完整反馈，不会被黑色子框遮住。split 视图里的改动行仍会铺上各自的内容层衬底（与 `legacy` 的分层方式一致），保证增删差异始终清晰。发生变化的词会按各自所在的底色重新挑选可读颜色，不会因为高亮而丢失；上下文和未改动文本继续保留原有的语法高亮颜色。
- **行衬底色值**：通过将主题的 diff 词色极少量混入终端实际背景推导而来，没有引入新的配色表。暗色真彩终端下约为 `#101b13`（新增）和 `#201214`（删除），浅色终端为接近白色的淡绿与淡玫瑰。256 色档直接使用显式色槽——暗色 `22`/`52`（`#005f00`/`#5f0000`），浅色 `151`/`181`（sage/rose）——避免被量化成类似 palette 59 的中灰；仅有 ANSI 颜色名的主题在真彩档也会回退到这组显式色槽。16 色档则退回终端底色，只用词色区分增删。
- **词色对比度调整**：
  - 普通 unified 优先使用主题的 `diffAddedWord` 和 `diffRemovedWord`；如果对卡片底色对比度不足 4.5:1，会按同色相自动提亮或压深。
  - split 的改动词如果压在行衬底上不足 4.5:1，真彩档会按同色相调整，256 色档在暗底用 `194`/`224`（浅绿/浅玫瑰），在亮底用 `22`/`52`。
  - 对于选区/悬停高亮底上的词色（用于 unified 增删词和 16 色 split）：由于 256 色暗高亮底会量化成接近 palette 59 的中灰（原主题词色压上去对比度只有约 2.6:1 和 2.0:1），因此显式改用 `194`/`224`，亮高亮底沿用 `22`/`52`。真彩档会基于真实高亮底调整到 4.5:1；16 色档使用终端自身的绿/红槽位（实际对比度受用户 0–15 调色板影响，回归测试仅在默认深色盘上断言不低于 2:1，且高亮底可能与终端黑落在同一槽位）。

真实渲染回归测试会直接读取终端单元格的前景与背景色（覆盖 unified/split、oldText-newText 与 patch、上下文与改动词）：

- 验证增删行底色各自不同且贴近黑/白、上下文行不被染底、选中和悬停高亮可见。
- 验证未改动的关键词和变量前景色在 `cli-highlight` 上色后与 `legacy` 逐格一致，改动词对所在底色达标。
- 120 列双栏回归还会额外检查选中与悬停时 old/new 行底始终不同、卡头/粗 gutter/上下文反馈保留、鼠标移出后内容衬底仍在，以及 `legacy` 原外观和显式覆盖不受影响。

## Job 进度线

`kinds.job.progressStyle` 只控制**对话中的后台任务卡片**：`pi-like` 默认为 `line`，`legacy` 默认为 `bar`。显式配置优先，非法值回退到方案默认。

`line` 样式由一条细线、弱化的剩余线段以及上游提供的原始 `n/m` 计数组成：

- 没有背景填充、不使用块状字符、不额外计算百分比。
- 颜色只代表进度比例：前 1/3 用主题 `accent` 色，中段用 `ide` 色，后段用 `success` 色。细线与计数使用相同的阶段色，不会把低进度染成表示失败的红色，也不会改变任务的状态符号或实际状态。
- 当进度文本不是 `n/m` 格式（如自由文本、`0/0` 或溢出的数字）时，原样展示文本而不编造进度条；当分子超过分母时，只将视觉比例钳制到满格，数字照常显示。
- 卡片标题栏维持原有的固定窄槽：计数较长时会先缩短细线；如果连两格细线都放不下，则只显示计数（仍保留可解析比例对应的阶段色），并按槽宽截断，避免把标题或基础字段挤到下一行。

配置示例（在 `pi-like` 下单独切回块状进度条）：

```json
{
  "preset": "pi-like",
  "kinds": {
    "job": { "progressStyle": "bar" }
  }
}
```

`line` 样式仅用于对话卡片；共享的 `/jobs` 面板不读取这个配置，在任何方案下都保持块状 `bar`；`legacy` 的对话卡片也保持原样。切换 `preset` 不会清除这里的显式覆盖。

## 用户卡面与终端底色

在 `pi-like` 方案下，用户卡面（用户消息和团队消息共用同一套样式）会跟随**终端实际底色**动态计算：系统通过 `ThemeProvider` 的 `useTerminalBackground()` 获取 OSC 11 探测到的终端背景色（未探测到时按主题明暗取纯黑或纯白），然后将当前主题正文色的约 12% 混入这个背景色中，形成一层柔和且易于定位的实色衬底（深色主题略微提亮，浅色主题略微压暗）。

> 注意：如果用户强制指定了主题、终端未返回背景探测结果，或探测结果与当前主题明暗不符而被丢弃，系统只能回退到纯黑/纯白基准，无法保证同样贴合实际终端底色的观感。

用户输入的文字颜色默认保持 `userPromptLabel`，`pi-like` 默认不加粗。你可以用 `kinds.user.foreground` 和 `kinds.user.bold` 覆盖（例如 `"user": { "foreground": "userPromptLabel", "bold": false }`）。原有的 `background`、边框和内边距配置继续有效；团队消息共用这套卡面背景，但保留自己的发送者文字样式。

这套用户卡面不会借用悬停色或选中高亮色（`dark` 主题下的 `userMessageBackgroundHover` 是高饱和蓝 `#3B5BDB`，`messageActionsBackground` 是选中反馈色），因此选中卡片时依然能清晰分辨。

不同色档下的降级策略如下：

| 色档 | 用户卡面默认底色 |
| --- | --- |
| 真彩（逐通道色） | 终端底色与正文色约 12% 的实色混色（深色底上约 `#1c1c1b`），保持柔和但可辨的层次 |
| 256 色 | 匹配最接近的中性灰阶槽位（232–255）；近白取到 `255`（`#eeeeee`），近黑取到 `232` |
| 16 色 / 关闭颜色 | 不填充背景 |

在 256 色下刻意避开了 6×6×6 色彩量化（否则像 `rgb(30,30,34)` 这样的近黑色会被抬成 `palette 59` 即 `#5f5f5f` 的大块灰底），改为直接映射终端自带的中性灰阶。16 色档无法表达足够淡的底色，铺高饱和色反而违背“接近透明”的意图，因此直接留空不填，但卡片间的空行和原有缩进依然保留。仅有 ANSI 颜色名的主题（如 `dark-ansi`、`pink-ansi`）无法做逐通道混色，即使在真彩下也按 256 色灰阶槽位绘制。另外，如果你显式配置了 `background`，它不属于预设底面，任何色档下都会按你指定的颜色原样绘制。

## 回退与维护

如果要完全恢复旧版外观，只需删除用户配置和部署配置中的 `cardStyles`，或将生效配置设为 `{ "preset": "legacy" }`（注意不要保留 `common` 或 `kinds` 覆盖）。整个过程不需要迁移会话数据。

下游实现集中在以下文件：`src/cardStyles.ts`、`src/components/cardSurface.tsx`、`src/components/diffAppearance.ts` 和 `src/components/Chat/JobLineProgress.tsx`。各卡片只接入了表面属性、内容宽度作用域、diff 外观数据、进度样式以及原有的折叠调用点，并未改动状态映射逻辑、diff 解析与核心算法，也没有改动交互面板。

上游更新后，可运行以下命令做完整回归验证：

```sh
node --import tsx/esm scripts/downstream/verify-card-styles.ts
node --import tsx/esm scripts/downstream/verify-card-rendering.tsx
FORCE_COLOR=2 node --import tsx/esm scripts/downstream/verify-card-rendering.tsx
FORCE_COLOR=1 node --import tsx/esm scripts/downstream/verify-card-rendering.tsx
node --import tsx/esm scripts/downstream/verify-card-demo.tsx
```

布局回归测试会使用与演示脚本相同的场景覆盖 `MessageList`（其中 `verify-card-demo.tsx` 会检查正文可见以及滚动时不出现空白带）；颜色矩阵测试会直接读取终端单元格的实际前景色和背景色，而不仅检查配置字符串。

开发调试时，可以使用无需后端和凭据的独立演示脚本（需在真实 TTY 中运行）：

```sh
node --import tsx/esm scripts/downstream/card-styles-demo.tsx --width 40
# inline 模式或加载自定义用户配置文件：
node --import tsx/esm scripts/downstream/card-styles-demo.tsx --inline --settings scripts/downstream/fixtures/card-styles.settings.json
```

演示脚本会自行隔离 `HOME` 目录，使用 `auto` 主题探测终端背景（无响应时回退深色），并在加载 UI 前设置 `DSH_TUI_TMUX_TRUECOLOR ??= '1'` 以保留真彩暗面的细阶（显式传入 `FORCE_COLOR=2/1` 仍会正常降级；正式应用则会按上文规则检查 tmux 客户端能力）。演示脚本不调用后端，也不影响稳定安装。操作快捷键：`Alt+1/2/3` 切换旧版/新方案/边框覆盖，传入 `--settings` 时 `Alt+4` 切回文件配置，`Alt+o` 全部展开，方向键或 `j/k` 滚动，`Ctrl+C` 退出。
