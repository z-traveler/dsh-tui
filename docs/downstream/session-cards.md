# 会话事实卡片

`sessionCards` 是一个**默认开启**的显示开关，把三类已经持久化的会话记录渲染成对话流中的卡片：

1. DSH 注册表命令的执行结果（`command/run` / `command/done`）
2. 用户显式加载技能时注入的正文（`skill-invocation`）
3. 生产者声明为 `source.form: 'notice'` 的通用上下文通知

三类记录对模型可见的规则保持原样：命令的 `command/run` 和 `command/done` 仍然是仅记日志（log-only）的记录，从不进入模型消息；技能正文和上下文通知则**继续传给模型**，卡片只是为同一份已保存的数据增加可视化展示。因此，这个开关不会新增任何命令、不发起模型请求、不改写持久化事件，也不会改变模型看到的上下文内容。

## 命令结果卡片

DSH 的 `dsh-commands` 在执行用户输入的命令时，会记录两条仅记日志的事件：`command/run`（包含 `commandId`、命令名、可选的原始输入）和对应的完成事件 `command/done`（包含同一 `commandId`、`success`/`error` 状态、可选的完整正文 `text`，以及可选的 `sourceEventSeq`）。它们都不是模型消息。开启 `sessionCards` 后，TUI 会按 `commandId` 把这一对事件组合成一张命令结果卡片：

- **默认折叠**：显示一行标题（`⏵ /命令名 原始输入`）和一行摘要（取正文首个非空行，最多 240 个显示单元），不自动展开全文。
- **展开查看全文**：按全局快捷键 `Ctrl+O`，或点击该行 / 在消息选择模式中按 `Enter` 逐条展开，即可看到完整正文。这里取消了旧版 200 行 / 65536 UTF-16 码元 / 每行 4000 显示单元的截断限制，展开后可以随对话流滚动读到最后一行。
- **错误命令**：标题改用 `✗` 和错误色显示，正文保留命令自己的失败文本，同时保留原有的错误 toast 提示。
- **避免重复提示**：开启后，注册表命令的结果不再通过 dispatcher 的本地报告路径（`local` 和 `local-output` 行）再铺一遍，成功时也不再用 toast 复述——同一条结果只展示一次。只有失败时的错误 toast 会保留，与错误卡片同屏提供醒目的颜色和限时提醒。
- **不生成多余卡片**：执行成功但没有任何正文的命令不出卡片（例如只代表“已执行”的 `/技能名` 命令）。如果 `command/done` 带有 `sourceEventSeq`，说明更早的权威记录已经提供了更完整的展示（例如 `/compact` 的压缩检查点），此时既不出命令卡片，也不再弹 toast。

所有交互与既有逻辑完全一致：折叠和展开纯粹是 UI 状态，不会重新执行命令或请求模型；草稿消耗、取消操作以及进入 executor 前就被拒绝的提示（例如未知命令仍提示 `command-not-found`）都保持原样。

## 已知取舍

- 直接输入不带参数的 `/goal`（DSH 注册表行的状态查询）不适合用单行 toast 展示，因此上游会直接在对话流中打印一段类似 `/plugins` 的长报告。开启 `sessionCards` 后，它与其他注册表命令一样变成默认折叠的卡片，需要按 `Ctrl+O` 展开才能查看具体目标和轮次。这是通用命令卡片的统一折叠规则，不是专门针对 `/goal` 的特殊处理；`/goal` 面板自身的状态展示不受影响，关闭 `sessionCards` 后也会恢复打印整块报告。

## 显式技能卡片

当用户显式加载技能时（无论是输入 `/name` 还是 `#skill:name`，在 core 里产生的是同一条记录），core 会在用户的普通消息之后追加一条来源为 `skill-invocation` 的注入消息，内容就是当时实际交给模型的标准指令文本。开启 `sessionCards` 后，这条记录会渲染成一张独立的技能卡片：

- **默认折叠一行**：显示 `[技能] 名字 · 已加载指令`，标签文本随界面语言和主题变化。
- **展开查看正文**：交互方式与命令卡片相同，展开后直接显示 core 当时保存的完整正文。它不会重新读取磁盘上的技能文件，不会从包装标签里猜测名字，也不会请求模型。注意，这张卡片证明的是**指令已加载**，不代表后续任务执行成功。
- **保留原输入与会话状态**：用户自己发出的那一行（包含 `/name` 或 `#skill:` 原文）仍保留为普通的用户消息；技能卡片不会改变 `lastUserText`、会话回退位置、持久化事件或传给模型的消息列表。
- **其他注入内容不变**：插件上下文等其他注入内容维持上游“不渲染成人工用户气泡”的行为。
- **仅限追加记录**：只有以 `append` 方式写入的注入才会生成卡片；`surfaceOp` 为 `replace` 的替换副本只对模型可见，不会额外出卡（旧版日志缺少 `surfaceOp` 字段时按 `append` 处理）。

## 通用上下文通知卡

只要任何生产者在持久化的 `user/message` 上声明了通用的 `source.form: 'notice'` 和 `summary`，TUI 就会把它渲染成一张独立的通知卡片。这里不要求特定的插件名、`name` 字段或插件私有字段，无论 `source.kind` 是什么，都走同一套逻辑。折叠摘要取自 `source.summary`，完整正文取自消息的 `content`：

- **默认折叠一行**：显示 `[通知] 摘要`。采用中性标签，不从文本猜测严重级别，也不会额外弹出 toast、系统通知或响铃。
- **展开查看正文**：交互方式同上，展开后直接展示持久化消息的完整正文。对长 CJK、emoji 或 ANSI 内容按渲染安全规则清理后完整呈现，不分页、不静默截断。
- **保留原始位置与元信息**：卡片保留原消息的 `id`、事件 `seq` 和 `time`；它不是用户气泡，也不会改变 `lastUserText`、会话回退位置或模型消息。
- **仅限追加记录**：同样只有 `append`（或旧日志中缺少 `surfaceOp` 标记）的消息才会生成卡片；`replace` 替换副本只对模型可见，不会重复出卡。
- **专属分支优先**：已有的专属通知分支（例如 `model-selection`）优先级高于通用通知卡片，保留原有的提示文案。

## 恢复、分页与内存

三类卡片的数据都直接来自持久化日志，因此实时对话、`/resume` 恢复以及“加载更早”分页看到的都是同一条记录。为了控制会话窗口的内存占用，当卡片滚出当前转录窗口时，内存中的正文会降级为预览；通过 `loadOlder` 向上加载时，系统会分别按 `commandId`（命令卡片）或记录自身的 `seq`（技能和通知卡片）从日志中重新恢复完整正文。

## 配置

该功能默认开启，无需额外配置。如需关闭，在 `cordis.patch.yml` 或 `cordis.yml` 的 `dsh-tui` 插件行中显式设置：

```yaml
config:
  sessionCards: false
```

关闭后，对话流恢复上游的原有行为：注册表命令结果走 dispatcher 的本地报告路径，注入的技能正文和所有合法的 `notice` 消息只对模型可见。
