# 原生子代理卡片固定区

私有下游提供了 `subagentInputDock` 选项（默认关闭）。你可以在 `/settings` 的「对话与输入」中开启「运行中的子代理固定在输入框上方」，也可以在 `~/.dsh-tui/settings.json` 现有的 `values` 中合入以下字段（保留你的其他设置）：

```json
{
  "version": 1,
  "values": {
    "subagentInputDock": true
  }
}
```

在设置页修改会立即生效；手工编辑配置文件后需要重启。通过 DSH CLI 挂载插件时，也支持在插件配置中设置 `config.subagentInputDock: true`。

## 一份实时卡片，原位置留静态卡片

开启后，正在运行的原生 `SubagentMessage` 卡片会直接绘制在对话转录区的底部固定区，而不是另外造一套简陋的替代卡片。卡片原有的标题、状态和模型信息、工具行、活动流水、点击查看详情以及 `⤢` 主屏查看操作全部保留。

固定区的布局位置和让位优先级如下：

- **停靠位置**：紧贴对话区底部，位于运行状态行、todo、回顾与插件状态行、审批面板以及输入框的上方；这些底部原有的元素位置不变，继续贴着输入框。
- **浮层遮挡**：自动补全选择器等瞬态浮层依然以输入框所在的输入簇顶边为基准向上展开，必要时可以直接覆盖在固定区上方。
- **矮终端让位**：当终端高度太小、底部元素放不下时，位于最上方的固定区会整体让位隐藏，优先保证输入框和运行状态行完整可见。

与此同时，历史对话区里原来那个位置会保留同一张卡片的折叠表头作为**静态占位卡片**：

- 沿用同一张卡面样式，但不转圈、不实时刷新耗时、token 和工具计数，状态位固定显示「运行中 · 实时卡片在下方」。
- 它的高度只由卡片样式决定，不随工具或输出增加而跳动，确保原位置的滚动基线稳定；点击依然可以打开详情，按 `⤢` 仍可在主屏查看。
- 当子代理任务完成、失败、取消或进入未知状态时，它会退出固定区，原位置恢复成正常的完整历史卡片。

这项功能纯粹改变界面展示方式，不会删除、复制或修改会话事实，不移动持久化记录，也不干涉子代理的执行。主会话继续输出新消息、上下滚动对话记录或打开子代理侧栏，都不会把固定区带走。如果全屏编辑器或其他输入场景临时占用了输入区，固定区会自动让位，同时把历史位置的卡片恢复成正常状态，避免看不到唯一的实时视图。关闭该配置后，一切恢复原有的对话展示方式。`inline` 模式下同样遵循现有的无鼠标限制，请使用 `Ctrl+A` 打开子代理面板。

## 原卡片的紧凑与折叠

在固定区里，所有并行运行的子代理成员共用**同一张外层卡面**（共用背景、边框和内边距），成员之间不再各自画边框或留透明空隙。同时，每一条依然使用原有的原生卡片组件，保留各自的标题、状态和查看动作。在 `legacy` 风格下固定区默认透明；在 `pi-like` 或显式配置了背景时，整个固定区会统一绘制底色。

固定区会根据当前可用的垂直空间自动切换三种布局模式：

1. **完整布局**：保留工具行以及最多三行活动流水。
2. **紧凑布局**：保留工具行以及最新的一行活动流水。
3. **折叠布局**：只保留原卡片的表头。

内部排版细节：

- 当子代理还没有工具调用记录时，回复预览紧贴标题显示，空白的工具占位行留在条目末尾，保证输入框和后面其他成员的位置不会上下抖动；一旦有工具记录，首行显示最近的工具，紧接着下面显示回复预览。
- 回复预览会把正文里的换行符替换为空格，每条固定占一行显示高度，绝不收缩或随流式内容变动上下空白。会话数据里保存的原文和换行符不受任何影响。
- 外观样式直接复用 `cardStyles.kinds.subagent`：包括 `pi-like` 下的运行态背景、深浅主题适配，以及公共/类型级的边框、颜色、内边距和间隔覆盖；`legacy` 下默认保持透明和无边框。

固定区的高度预算规则：

- 外层卡片的边框、内边距和间隔只计算一次，整块固定区最多占 8 行，同时受限于终端总高度的约 1/4，并至少为底部其他界面元素预留约 12 行空间。
- 运行中的任务过多时，固定区会把卡片折叠并明确展示总运行数、当前可见数和被折叠的数量（点击数量即可打开原有的子代理面板）。例如在 100×40 的 `pi-like` 演示中追加任务到 14 个时，会显示类似 `14 running · 6 shown · 8 folded` 的汇总条。
- 如果终端太矮或用户的个人边框/内边距过大，导致连一个折叠表头都放不下时，固定区只显示可点击打开面板的数量入口，绝不画出一张被裁掉一半的残缺卡片。

## 隔离演示

在仓库根目录运行以下命令启动交互演示：

```sh
node --import tsx/esm scripts/downstream/subagent-dock-demo.tsx
node --import tsx/esm scripts/downstream/subagent-dock-demo.tsx --inline
```

演示默认使用 `pi-like` 风格，启动后立即显示 `Review` 和 `Tests` 两个并行任务。每个成员从模拟 `Read` 调用开始，每 1.5 秒交替完成当前工具并启动下一个工具，循环演示 `Read` → `✓Read` → `✓Read · Grep` → `✓Grep`，下方同步展示模型回复。

- `single`、`parallel`、`workflow` 以及追加出来的成员都会模拟工具事件；当 workflow 推进阶段或全部完成时，会先结算当前还在运行的工具。
- 工具行来自真实转换后的 `toolCalls` 数据，而不是把正文强行改成工具名；这些事件仅用于本地演示，不会真的读文件、执行命令或调用模型。
- 建议终端尺寸至少 `60×24`，在 `100×40` 下可以看到更完整的回复正文（折叠布局依然只显示表头）。加上 `--legacy` 参数可以从旧版外观开始演示。

| 演示快捷键 | 操作 |
| --- | --- |
| `Alt+6` | 单个子代理 |
| `Alt+7` | 两个并行子代理（默认） |
| `Alt+8` | workflow：规划 → 两路审查 → 汇总 |
| `Alt+9` | 手动推进 workflow 阶段，并结算当前阶段的所有成员 |
| `Alt+5` | 循环切换风格：`legacy` / `pi-like` / `pi-like`＋描边内边距 |
| `Alt+1` | 显示或隐藏固定区 |
| `Alt+2` | 向所有场景（包括 workflow）追加 12 个并行成员 |
| `Alt+3` | 立即完成当前所有任务 |
| `Alt+4` | 重置当前场景 |
| `Ctrl+C` | 退出并清理临时 `HOME` |

切换或重置场景会清空演示草稿并重建隔离会话。workflow 场景使用假的模拟子会话，走真实的 DSH workflow 成员和子输出事件展示流程，不会执行真正的 workflow 工具、调用模型或读取真实凭据。通过 `Alt+2` 额外追加的 workflow 成员同样会在下一阶段推进时结算；如果在已完成的流程上继续追加任务，它们会被标为 `Parallel extension`，继续推进即可结算。

## 实现要点与维护说明

- **一致的挂载条件**：`Chat` 使用同一个布尔条件来同时控制“挂载底部固定区”和“把历史位置切为静态占位卡片”。固定区挂在底部区域的最上方，不放进输入簇内部，以免把输入簇上的浮层基准位置一起顶高。
- **行高缓存稳定性**：`MessageList` 的行 memo 和高度缓存签名里包含了上述条件，确保在开关切换或任务进入终态时能正确重测高度。同时，运行中的历史静态卡片高度只取决于已经包含在行签名里的卡片样式，因此工具数和输出行数的不断变化不会让它的高度缓存失效，避免了屏幕外的历史卡片高度变化把 `inline` 模式下的输入区来回顶动。
- **不影响默认行为**：原卡片组件新增的可选 `density` 和静态模式开关只供固定区和历史静态卡片使用，缺省参数保持原有的对话转录渲染行为。所有展示数据直接读取现有的 `SubagentState` 和 `SubagentRow`，不在界面层重复生成或改写会话数据。

升级或修改相关代码时，请依次运行以下验证脚本：

1. `verify-subagent-reference-height.tsx`：检查屏幕外静态卡片的虚拟高度与输入区位置不会随子代理活动而变化。
2. `verify-subagent-dock-stability.tsx`：检查包含换行符的连续流式更新、工具位切换、正文槽位稳定性和共享外层卡面。
3. `verify-original-subagent-dock.tsx`：检查 workflow 原卡片标题位于新主输出之后、输入区之前，历史位置显示为静态卡片，运行状态行位于固定区与输入框之间，且选择器浮层与输入框之间不会夹入固定区。

同时还需复验：开关实时切换、任务终态恢复原卡片、`⤢` 主屏查看、`pi-like`/`legacy` 卡面差异、矮终端高度下的让位表现，以及 `Alt+2` 追加成员后的阶段结算。
