# 插件模态浮窗使用窗口栈并向关键宿主交互让位

插件模态浮窗采用窗口栈管理，不沿用交接文档的首版单窗口限制；用户明确选择堆栈，以 Pi 的浮窗交互模型为参考。该能力只承载通用插件内容，不承担模型测速等消费者业务，既有全屏场景默认行为保持不变。

审批、问卷及托管对话框出现时，隐藏浮窗并保留状态，由关键宿主交互独占输入；交互结束后恢复仍有效的浮窗。已经关闭或因插件卸载而释放的浮窗不得恢复。此规则保留 Pi 的交互连续性，但补上其仅转移焦点、浮窗仍可能遮挡问答的缺口。

浮窗活动时，Esc 与 Ctrl+C 均由宿主兜底关闭当前交互浮窗，不能穿透为聊天取消、草稿清理或后台任务取消。关键宿主交互期间，这两个键归关键交互，不得借此操作隐藏的浮窗。

注册项表示窗口类型，每次打开创建独立窗口实例，允许同一注册项同时存在多个实例；消费者可自行保存句柄以复用窗口。按实例关闭或因 owner 卸载而移除底层窗口，不连带关闭其他实例，也不默认建立父子级联关系；焦点归还给仍有效的栈顶窗口，否则归还聊天。插件只能操作自己拥有的实例。

切换会话时关闭整个浮窗栈，防止窗口继续操作旧会话上下文。临时进入设置等宿主页面时隐藏整个栈，返回原聊天后恢复仍有效的实例；非聊天页面拒绝新开浮窗。关键宿主交互期间同样拒绝新的开窗请求。

用户已确认上述行为，并将后续非 P0 的实现细节交由实现者依据现有契约与最小必要原则判断，不逐项进行产品问答。若发现目标或授权范围冲突、必须改动官方宿主/渲染器，或无法满足关键交互与会话隔离，仍须暂停并上报。
